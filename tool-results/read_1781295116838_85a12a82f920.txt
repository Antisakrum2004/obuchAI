     9→## 1. Project Overview
    10→
    11→- **Что это**: AI Тренажёр для 1C-разработчиков — Duolingo-style геймифицированная платформа обучения навыкам работы с ИИ
    12→- **Задача**: Научить 1C-разработчиков промпт-инжинирингу, работе с AI-агентами, дебаггингу через решение задач
    13→- **Домен**: obuch-ai.vercel.app
    14→- **Репозиторий**: github.com/Antisakrum2004/obuchAI (синхронизирован с workspace)
    15→- **Стек**:
    16→  - Frontend: Next.js 16 (App Router) + React 19 + Tailwind CSS 4 + shadcn/ui
    17→  - Backend: Next.js API Routes (serverless)
    18→  - БД: Neon PostgreSQL (serverless) через Prisma 7 + raw SQL
    19→  - Аутентификация: NextAuth.js v4 (JWT strategy)
    20→  - Стейт: Zustand 5 (клиент)
    21→  - Анимации: Framer Motion 12 + canvas-confetti
    22→  - Деплой: Vercel (standalone output)

   201→### Как идут данные
   202→
   203→1. **Вход**: Пользователь → `/login` → Google OAuth / Demo / Admin → NextAuth JWT → редирект на `/dashboard`
   204→2. **Профиль**: Страница загружается → Zustand store (клиент) → `/api/me` или `/api/dashboard` → raw SQL → Neon
   205→3. **Решение задачи**: POST `/api/challenges/[id]/submit` → валидация ответа → UPDATE users (xp, streak, level) → INSERT challenge_attempt → проверка achievements → ответ клиенту → Zustand update → confetti/animation
   206→4. **JWT refresh**: Каждый запрос → jwt callback → `SELECT role, xp, level, streak FROM users WHERE id=$1` → JWT обновляется свежими данными
   207→5. **Feature flags**: `/api/settings` (revalidate 30s) → `useAppSettings` React context → все компоненты читают флаги
   208→6. **Реферал**: Cookie `ref` → при регистрации → XP бонус обоим → `xp_logs` запись
   209→7. **Квиз**: QuizBlock (клиент) → single-question режим с таймером 30с → POST `/api/knowledge/quiz/submit` → валидация → `xpForQuiz()` расчёт XP → UPDATE users (xp, level) → INSERT xp_logs → Zustand update

   213→## 3. Core Modules
   214→
   215→### 3.1 Auth (`src/lib/auth.ts` — 419 строк)
   216→- **Провайдеры**: Google OAuth (условный — включается если GOOGLE_CLIENT_ID настроен), Demo login (email), Admin login (username/password)
   217→- **Стратегия**: JWT, maxAge 30 дней, httpOnly cookies
   218→- **Колбеки**: `signIn` (find-or-create user + referral processing), `jwt` (refresh from DB on every request), `session` (inject custom fields), `redirect` (prevent loops)
   219→- **Проблема**: Admin credentials захардкожены (`admin/admin123`), 8 `as unknown as Record` кастов
   220→
   221→### 3.2 Database (`src/lib/db.ts` — 75 строк)
   222→- **Dual access**: `pool` (raw SQL через `@neondatabase/serverless`, 85% запросов) + `db` (PrismaClient через `PrismaNeon` adapter, admin/auth routes)
   223→- **Hot-reload protection**: Глобальные синглтоны через `globalThis` (не пересоздаётся при HMR)
   224→- **WebSocket fallback**: `ws` пакет для локальной разработки (Neon требует WebSocket в Node.js) — вынесен на уровень модуля (v0.13.0)
   225→- **Connection pooling** (v0.13.0): `connectionTimeoutMillis: 5000`, `idleTimeoutMillis: 30000`, `max: 10`, `ssl: { rejectUnauthorized: false }`
   226→- **Shared pool** (v0.13.0): Prisma adapter переиспользует тот же глобальный пул (раньше создавался второй пул на каждый холодный старт)
   227→- **Проблема**: Pool/PrismaNeon type incompatibility — `as unknown as PoolConfig` каст
   228→- **✅ Neon pool timeout — РЕШЕНО**: Connection pooling улучшен в v0.13.0 (shared pool + таймауты), проблемы с timeout устранены
   229→
   230→### 3.3 Gamification (`src/lib/gamification.ts` — 182 строки)
   231→- **XP формулы**: `xpForLevel(n) = 100 * n^1.5` (экспоненциальный рост)
   232→- **Множители**: Time-based (100% → 10% за 30с блоки), No-hearts penalty (50% XP)
   233→- **Streak бонусы**: 7 дней → +200 XP, 30 дней → +1000 XP
   234→- **48h правило**: Streak ломается если нет активности >48 часов
   235→- **Категории**: prompting, agents, tools, automation, 1c, debugging, workflow, review
   236→- **Сложности**: easy (25 XP), medium (50 XP), hard (100 XP)
   237→
   238→### 3.3.1 Grade System (v0.17.0) — `getGradeName()`, `getGradeColor()` в `src/lib/gamification.ts`
   239→- **Механика**: Пользователи получают текстовый ранг (grade) в зависимости от уровня
   240→- **Таблица рангов**:
   241→
   242→| Уровень | Ранг (grade) | Цвет | CSS-класс |
   243→|---|---|---|---|
   244→| 1–4 | Начинающий | Изумрудный | `text-emerald-400` |
   245→| 5–9 | Специалист | Синий | `text-blue-400` |
   246→| 10–14 | Мастер | Фиолетовый | `text-purple-400` |
   247→| 15–19 | Про | Янтарный | `text-amber-400` |
   248→| 20–24 | Звезда | Жёлтый | `text-yellow-400` |
   249→| 25+ | Легенда | Розовый | `text-rose-400` |
   250→
   251→- **Функции**: `getGradeName(level)` → строка с названием ранга, `getGradeColor(level)` → CSS-класс цвета
   252→- **Отображение**: XPBar компонент показывает `{level} {gradeName}` — цифра уровня + текстовый ранг рядом (шрифт `text-[10px]`, цвет `text-muted-foreground`)
   253→
   254→### 3.3.2 Quiz Gamification (v0.17.0) — `xpForQuiz()`, `QUIZ_TIME_PER_QUESTION` в `src/lib/gamification.ts`
   255→- **Таймер**: 30 секунд на вопрос (константа `QUIZ_TIME_PER_QUESTION = 30`), цветовая индикация: зелёный (>20с), янтарный (>10с), красный (≤10с)
   256→- **Режим отображения**: Single-question — один вопрос за раз (не все сразу), с анимированными переходами между вопросами
   257→- **Автопереход**: При истечении таймера вопрос помечается как без ответа, автоматически переход к следующему; на последнем — автопроверка
   258→- **XP за квиз**: `xpForQuiz(correctCount, totalCount, difficulty)` — easy=5/medium=10/hard=15 XP за каждый правильный ответ, +50% бонус за идеальный результат (все правильные)
   259→- **Без сердечек**: Квизы НЕ используют hearts — неправильные ответы просто не приносят XP
   260→- **API**: POST `/api/knowledge/quiz/submit` — валидация (статья существует + есть квиз), расчёт XP, UPDATE users (xp, level, lastActiveAt), INSERT xp_logs (reason='quiz'), возврат { success, xpEarned, totalXp, newLevel, grade }
   261→- **Навигация**: Кнопка «Следующий вопрос» / «Проверить ответы» (на последнем), точечная навигация для прыжка между вопросами
   262→
   263→### 3.4 User Store (`src/store/user-store.ts` — 50 строк)
   264→- **Zustand 5**: id, name, email, image, role, xp, level, streak, maxStreak, completedChallenges, rank, isLoading
   265→- **Методы**: setUser, addXp, setLevel, setStreak, setLoading, reset
   266→- **Связи**: Dashboard, header (XP bar), profile, challenge result — все читают из стора
   267→- **v0.17.0**: После прохождения квиза — `addXp` и `setLevel` вызываются с данными из `/api/knowledge/quiz/submit` response
   268→
   269→### 3.5 Challenge System
   270→- **Страницы**: `/challenges` (список с фильтрацией), `/challenges/[id]` (решение)
   271→- **API**: GET список, GET по ID, POST submit
   272→- **Типы задач**: multiple_choice, ordering, workflow_build
   273→- **Валидация**: Статическая (сравнение с correctAnswer), нет AI-оценки свободных ответов
   274→- **Cooldown**: Задержка повторного решения одной задачи
   275→- **Контент**: 100 задач в 7 категориях, описание + опции + объяснение + подсказки (JSON)
   276→
   277→### 3.6 Marathon Mode (`src/app/marathon/`, `src/app/api/marathon/`)

   529→### 🔴 СТАТЬИ И ЗАДАЧИ НЕ ОТКРЫВАЛИСЬ ПО КЛИКУ — ✅ ИСПРАВЛЕНО v0.15.1
   530→
   531→> **Статус**: ✅ РЕШЕНО — корневая причина найдена и устранена в v0.15.1
   532→> **Корневая причина**: Конфликт имён динамических сегментов в `/knowledge/` — директории `[slug]` и `[spaceId]` находились на одном уровне иерархии, что вызывало ошибку Next.js 16 Turbopack: `Error: You cannot use different slug names for the same dynamic path ('slug' !== 'spaceId')`. Эта ошибка крашила serverless-функцию при SSR ВСЕХ динамических маршрутов, вызывая полный таймаут без ответа (HTTP 000).
   533→> **Исправление**: Переименование `[spaceId]/learn/[articleId]` → `[slug]/learn/[articleId]`, обновление `params: Promise<{ spaceId }>` → `params: Promise<{ slug }>`, `p.spaceId` → `p.slug` в learn-странице.
   534→> **Локальная верификация**: `/challenges/[id]` — 150ms (200), `/knowledge/article/[id]` — 35ms (200). Все динамические маршруты работают.
   535→> **Production верификация**: ⏳ Ожидается деплой на Vercel (нужен ручной `vercel deploy --prod`)
